# 校验协议（Validation Protocol）——判定 · 盲测 · 差距分析

> v0.8.0 新增。S5 预测体系的判定端与方法论进化机制。
> 设计原则：**不让总结性规律直接成为设计底稿**——任何规则先冻结成显式算法，经盲测与实际比对、差距分析后才允许进化。

## 1. 判定（Resolution）

### 1.1 事件驱动判定

预测到点即判定，不等批量：
- 触发：resolution_window 到达（招股书公开 / 定价日 / 上市日 / 挂牌 +6m/12m）
- 流程：拉取判定数据 → 严格对照 `resolution_criteria.rule` 判定 → 写 resolution_record（S6）→ **predictions.yaml 与 resolutions.yaml 均只增不改**
- 判定必须列出"规则原文 vs 实际观测值"的显式比较（同 G9 精神）
- 禁止灵活解读：rule 写死的口径不适用时，判 `insufficient` 并记录原因，**禁止临时改口径后判定**
- **窗口判定口径（v0.2）**：回归类预测（P2）采用"窗口内任一交易日收盘 < 参照值"判真——依据 blind-batch-20260820 发现：时点口径噪声大（先锋案贴线后修复）、回归窗口可达 6-9 个月（恒坤案）

### 1.2 resolution-sweep（月度队列批量回填）

- **节奏**：每月一次（建议每月 15 日），固定日期、全量覆盖、无人挑选
- **动作**：①全 cohort 已上市样本的 1m/3m/6m 回归数据批量拉取（MCP）；②全部未决预测的状态扫描（哪些到点未判）；③刷新 ipo-cohort-backtest.md 的 F1/F3 统计与 regime 基准率
- **边界（防逐案例追踪）**：只按 cohort 维度操作（"2025-2026 全部科创板"），禁止"去看看某家公司怎么样了"式的单点查询；个案只在事件驱动判定（1.1）中出现
- regime 快照基准率刷新后，**对未决预测按重锚条款处理**：P1 类带 regime_note 的预测若基准率跨越退化阈值 → 判 `expired` 作废不计分，不静默沿用旧基准

## 2. 盲测（Blind Test）

> **定性声明（v2，2026-08-21 质检整改 Z2）**：回放盲测的基准率（F7/F8/F9）在全 cohort 上估算，盲测案例均在估算集内（小档位单案例可占 7-14% 基准权重，存在结构性循环）。因此回放盲测的性质是——**机制可执行性验证 + 方向性证据**，不是干净的样本外检验；任何文档/对外表述禁止使用"样本外验证/回测验证"叙事。真正的样本外证据只有活体预测（结果在未来）。留一法重算如未实际执行，禁止在算法卡中声明。

### 2.1 回放盲测（walk-forward）

- **case 选择（提前写死）**：算法卡冻结日之后起，按压力维度挑选——每批次至少含：①热 regime 1 例 ②非热 regime 1 例 ③regime 切换点 1 例；优先选低曝光标的（降低模型训练数据污染）
- **种子数据纪律（v2 增补，质检 B1）**：批次设计者向执行体提供的任何数字（发行价/PE/拟募等）必须标注"待核实"，执行体须以一手公告独立复核后方可作为输入——批次设计者是潜在的脏数据源（实测 6/6 起拟募口径错误被推翻）
- **信息屏障**：执行体（subagent，与算法卡作者分离）只允许使用信息截止日（= 标的上市前）之前的文件与数据；搜索到截止日后的信息必须丢弃并在推断记录中声明
- **工具禁用清单（v0.2，blind-batch-20260820 执行层发现）**：信息屏障内查询发行信息时，禁用会随附上市后字段的结构化行情工具（如东财 MCP 各 finance_data 接口——实测曾直接返回首日开盘/收盘价）；改用发行公告原文（上交所/披露易）或带截止年限定词的 WebSearch
- **推断**：严格按算法卡规则条文执行，输出 S5 格式推断记录（含规则引用：哪条 R 得出了哪个数字）；规则未覆盖的输入 → 明示"规则外判断"，不得冒充规则输出
- **污染标注**：执行模型训练数据可能含标的结局——推断记录必须标注该风险，低曝光 case 视为低污染、明星 case（宇树级）不作回放盲测

### 2.2 活体盲测（前瞻）

- 所有现行 S5 推演产物（智元 PLAN-20260820-001 等）天然是零污染盲测
- 活体结果与回放结果冲突时，**以活体为准**（回放有不可消除的残留污染）

### 2.3 压力维度（专挑会打爆算法的 case）

| 维度 | 检验目标 |
|------|---------|
| regime 切换点（如 2024Q4-2025Q1 上市） | R1 regime 判定灵敏度 |
| 极端 PE（>100x 或 <15x） | R2/R3 "定价贵贱无关论" |
| 首日暴涨（>400%） | R4 反向指标（n=7 假设的主战场） |
| 未盈利 + 高 PS | R5 盈利修正项 |

## 3. 判定与差距分析产物（均只增不改，存 knowledge/backtest/）

每批次三件套：
1. `inferences.yaml`——算法卡版本 + 输入 + 推断（S5 格式 + 规则引用）
2. `resolutions.yaml`——实际结果 + S6 判定记录（含 Brier 与基准率 Brier）
3. `gap-analysis.md`——差距结构分析：
   - **按规则粒度过账**，不报"总体准不准"：
     - R1 错 → regime 判定失灵（快照过期/阈值不当）
     - R2/R3 错 → 分支规则或基准率问题
     - R4 技巧分 ≤0 → 反向指标证伪 → 降级删除（C 级规则一审定生死）
   - **杠杆检验（v2 强制，质检 A3）**：任何合计 Brier/技巧分对比必须附单案剔除敏感性——单案贡献 >30% 时，禁止用合计差值作为定版依据（实测反例：批 9 P1 端爱科赛博一案占合计 65%，剔除后两轨完全打平）
   - **对抗复核（v2 增补，质检 B2）**：gap-analysis 初稿完成后，须由**独立 subagent**（非算法卡作者）做对抗性复核（检查计分错误、杠杆、口径漂移、结论过度），复核意见并入定稿——判定、过账、修订不得全程由同一人完成
   - 先写"哪里错"才允许提议改规则——**禁止先改规则再解释**
   - 规则修订 → 用户拍板 → 新版本算法卡，旧卡归档

## 4. 评分

- 二元预测：Brier = (forecast − outcome)²；outcome 真=1 假=0
- **技巧分 = 1 − Brier(算法) / Brier(regime 基准率)**：>0 才算算法有边际价值；≤0 表示不如直接查基准库
- 幅度带/区间带预测：按带内/带外判定，带概率按中点计 Brier（简化，v0.1 约定）
- expired / insufficient 不计分但计入覆盖率统计（覆盖率 <80% 时算法卡整体降置信）

## 5. 纪律

1. 算法卡冻结期内只读；修订只能经由差距分析 → 用户拍板 → 新版本卡
2. 盲测 case 选择标准先于结果知悉写死——禁止"挑顺眼的 case"
3. 推断、判定、差距分析三件套全部只增不改——天气预报原则：禁止下雨后修观测
4. 每季度（或每 3 批次盲测后）向用户提交算法卡健康报告：各规则技巧分、覆盖率、建议退役项
