# 前瞻信号监测框架（Signal Watchlist）

> GateKeeper 的风险推演不应止步于"识别风险"。对每项重大风险（🔴Critical / 🟠High），
> 必须建立前瞻信号清单——正向信号表明风险在缓解，负向信号表明风险在兑现。
> 这使保荐机构能够在项目推进过程中**持续监测**而非一次性判断。

> ⚠️ **内嵌案例时效警示**：本文件中的示例案例（九号公司、寒武纪、敏芯股份、孚能科技）均为**历史参照**（as_of 2019-2025），仅供信号设计模式参考。禁止将案例数值当作当前事实引用；使用时 `data_as_of` 必须填案例发生期。

---

## 1. 信号定义模板

每项重大风险（risk_level = critical 或 high）在输出时必须附加信号清单：

```yaml
risk_entry:
  id: "RISK-{node}-{role}-{seq}"
  # ... 标准字段 ...
  signal_watchlist:              # 前瞻信号清单
    risk_statement: ""            # 复述风险主张
    time_window:                  # 观察窗口（按风险类别差异化）
      category: "customer|tech|profit|market|regulatory"  # 风险类别
      duration: "2-4Q|4-8Q|8-12Q" # 默认窗口（由 category 决定）
      modifier: "early|standard|late"  # 可选，窗口内位置偏好
    priority_tier: "T1|T2|T3"    # 信号优先级层级（T1=结构级, T2=趋势级, T3=事件级）
    positive_signals:             # 风险在缓解的信号（≥2条）
      - signal: ""                # 具体可观测信号
        threshold: ""             # 判定阈值
        data_source: ""           # 数据来源
        implication: ""           # 若触发此信号，说明什么
    negative_signals:             # 风险在兑现的信号（≥2条）
      - signal: ""
        threshold: ""
        data_source: ""
        implication: ""
    what_must_go_right:           # 公司必须做对哪些事才能化解此风险（≥1条）
      - action: ""
        success_indicator: ""
    execution_proxy:              # 管理层执行力代理（可选，不计分）
      commitment_history: ""      # 历史承诺兑现情况
      launch_track_record: ""     # 新产品按时发布率
      pre_ipo_milestones: ""      # 上市筹备里程碑达成情况
```

### 时间窗口按风险类别差异化

> 窗口以风险条目的 `generated_at`（T0）为起算点——"2-4Q" 指 T0 之后第 2 至第 4 个季度。
> 输出信号清单时建议将窗口换算为绝对时间（如 "2026Q4-2027Q2"），避免接收方歧义。
> **事件锚定窗口**：对解禁、发行、补助退坡日等事件驱动风险，默认季度窗口不适用——
> duration 可填事件锚定形式（如 "解禁后 0-12M"、"发行后 6-24M"），并在 time_window 中注明锚定事件及日期。

| 风险类别 | 默认窗口 | 说明 | 测试案例 |
|---------|---------|------|---------|
| customer（客户结构） | 2-4Q | 客户集中度、大客户依赖 | 九号去小米化、寒武纪丢华为 |
| tech（技术路线） | 4-8Q | 技术路线更替、研发方向调整 | 敏芯专利战、寒武纪AI芯片 |
| profit（利润修复） | 4-8Q | V型利润恢复、毛利率修复 | 孚能毛利崩塌、九号利润回升 |
| market（市场地位） | 2-4Q | 市占率、竞争格局变化 | 孚能市占率下滑 |
| regulatory（政策监管） | 2-4Q | 政策变动、监管收紧 | 新能源补贴退坡 |

## 2. 信号设计原则

| 原则 | 说明 | 反例 |
|------|------|------|
| **可观测** | 信号必须是外部可验证的数据或事件 | ❌ "管理层诚信改善" |
| **有阈值** | 必须定义明确的定量或定性阈值 | ❌ "营收增长" → ✅ "营收连续2季度环比增长>10%" |
| **有时效** | 每个信号绑定一个观察窗口，窗口按风险类别差异化 | ❌ "长期来看" |
| **有含义** | 每个信号触发后，说明对风险判断的影响 | ❌ 只列信号不给含义 |
| **双面对称** | 正向和负向信号应对称设计 | ❌ 正向看营收、负向看专利 |
| **分层优先** | 品类/结构级(T1) > 趋势/财务级(T2) > 事件/舆情级(T3) | ❌ 季度利润波动推翻品类扩张判断 |

## 3. 按风险类别的信号模板

### 3.1 客户集中度风险

**典型风险**："前N大客户占比过高，单一客户流失将导致营收断崖"

| 正向信号（在缓解） | 负向信号（在兑现） |
|------------------|------------------|
| 第一大客户收入占比连续 2 期下降 ≥ 5pp | 第一大客户收入占比上升或持平 |
| 新增 ≥ 2 家年收入贡献 > 5% 的新客户 | 前 5 大客户中 ≥ 1 家公开宣布自研替代方案 |
| 前 5 大客户中有 ≥ 3 家签订 ≥ 3 年框架协议 | 主要客户采购量同比下降 ≥ 20% |
| 客户行业分布从单一行业扩展到 ≥ 3 个行业 | 主要客户应收账款逾期率上升 ≥ 10pp |

**必须做对的事**：在新客户开发上投入足够销售资源，同时保持老客户满意度；产品标准化程度提升以降低切换成本。

**示例（九号公司"去小米化"）**：
- ✅ 正向已触发：小米渠道占比从 52%→4%；自有品牌毛利率从 15%→42%；电动两轮车成为第二增长极
- ❌ 负向已规避：总营收未因去小米化而萎缩（维持100亿+）；未出现"去了小米但没有新客户"的空窗期

---

### 3.2 专利/IP 诉讼风险

**典型风险**："核心专利涉诉，败诉可能导致产品停售或大额赔偿"

| 正向信号（在缓解） | 负向信号（在兑现） |
|------------------|------------------|
| 涉诉专利数量不再增加（连续 6 个月无新诉讼） | 新增 ≥ 1 件核心专利诉讼（侵权或权属） |
| 已有诉讼取得有利进展（驳回/和解/专利无效宣告） | 一审败诉或不利裁决 |
| 公司绕开涉诉专利推出替代方案且获客户认证 | 涉诉产品线收入占比 > 10% 且无替代方案 |
| 专利数量和质量持续提升（年新增发明专利 ≥ 10 件） | 核心技术人员离职加入诉讼对手方 |

**必须做对的事**：提前做 FTO（Freedom to Operate）分析；储备绕行技术方案；核心人员签署竞业限制协议并严格执行。

**示例（敏芯股份专利战）**：
- ❌ 负向已触发：2019 年 7 月歌尔提起诉讼（IPO 关键期）；2023 年最高法终审败诉
- ✅ 正向已触发：涉诉产品收入占比极小（仅 20.6 万元）；实际控制人兜底承诺

---

### 3.3 毛利率可持续性风险

**典型风险**："毛利率剧烈波动或远高于同行，存在上市前调节嫌疑"

| 正向信号（在缓解） | 负向信号（在兑现） |
|------------------|------------------|
| 上市后连续 2 季度毛利率在招股书预测区间内 | 上市后首季毛利率同比下降 ≥ 5pp |
| 毛利率变动可用可验证的成本/定价因素解释 | 毛利率变动与原材料价格走势背离 |
| 可比公司毛利率同期同向变动 | 公司毛利率走势独立于行业趋势 |
| 分客户/产品毛利率披露透明且合理 | 会计师对收入确认出具非标意见 |

**必须做对的事**：保持与行业一致的定价和成本管理；避免上市前通过一次性操作（如压货、提前确认收入）美化毛利率。

**示例（孚能科技毛利崩塌）**：
- ❌ 负向已触发：上市后毛利率从 23.49%→0.54%（2021 Q3），下降 23pp；与宁德时代（28-32%）完全背离

---

### 3.4 技术路线单一风险

**典型风险**："仅聚焦单一技术路线，若行业技术转向则面临生存危机"

| 正向信号（在缓解） | 负向信号（在兑现） |
|------------------|------------------|
| 公司推出 ≥ 1 款采用新路线的产品（或发布明确路线图） | 行业头部企业集体转向另一路线 |
| 研发费用中新路线投入占比 ≥ 20% | 公司唯一技术路线的市占率连续下滑 ≥ 2 期 |
| 与采用不同路线的客户/伙伴建立合作关系 | 替代路线产品在核心性能指标上超越公司路线 ≥ 30% |
| 核心专利覆盖了下一代技术方向 | 行业标准/法规向不利于公司路线的方向修订 |

**必须做对的事**：保持"投产一代、储备一代、预研一代"的梯队；在新路线上有具体的研发投入和可验证的进展。

---

### 3.5 大客户流失/自研替代风险

**典型风险**："核心客户宣布自研替代方案，公司收入断崖式下跌"

| 正向信号（在缓解） | 负向信号（在兑现） |
|------------------|------------------|
| 核心客户自研进度延迟或公开信息显示遇阻 | 核心客户发布自研产品且性能达到公司产品 ≥ 80% |
| 公司产品迭代速度 > 客户自研替代速度 | 核心客户采购量同比下降 ≥ 30% |
| 其他客户收入增长弥补了核心客户份额下降 | 核心客户自研团队规模 > 公司研发团队规模 |
| 公司与核心客户签订 ≥ 3 年不可撤销采购协议 | 核心客户停止新项目合作，仅维持旧产品维护性采购 |

**必须做对的事**：不能把鸡蛋放在一个篮子里——在核心客户自研启动前就应多元化客户群；技术壁垒必须足够高，使自研成本 > 外购成本。

**示例（寒武纪丢失华为）**：
- ❌ 负向已触发：华为启动达芬奇计划；麒麟 990 弃用寒武纪→改用自研达芬奇架构
- ❌ 负向已触发：IP 授权收入从 1.17 亿→0.69 亿（-41%）；华为从第一大客户降为第四大
- ❌ 正向未触发：未能及时找到替代华为体量的大客户（招股书坦承）

### 3.6 信号优先级矩阵

> 当同一风险条目下的多条信号指向矛盾方向时，优先级更高的信号主导风险判断。
> 例如：T1 "品类扩张成功" 优先于 T3 "季度净利润低于200M阈值"——九号公司测试验证了这一规则的必要性。

#### 优先级层级定义

| 层级 | 标识 | 信号类型举例 | 权重 | 说明 |
|------|------|------------|------|------|
| Tier 1 | T1 | 品类/市场扩张、技术代际突破、行业范式转换 | 3 | 结构性变化信号，优先级最高 |
| Tier 2 | T2 | 利润率趋势改善、客户结构优化、竞争格局稳定 | 2 | 趋势性变化信号，中等优先级 |
| Tier 3 | T3 | 季度性盈利波动、短期费用上升、单季营收偏差 | 1 | 周期性/短期信号，优先级最低 |

#### 跨层级冲突处理

| 冲突场景 | 处理规则 | 测试来源 |
|---------|---------|---------|
| T1 正向 vs T3 负向 | T1 主导，T3 标注 `overridden_by_T1` | 九号公司：电动两轮车放量(T1+) vs 季度利润<200M(T3-) |
| T1 负向 vs T2 正向 | T1 主导，T2 标注 `overridden_by_T1` | 寒武纪：华为自研(T1-) vs 智能集群收入增长(T2+) |
| T2 正向 vs T3 负向 | 加权评估，不做自动覆盖 | — |
| 同层级冲突 | 正常汇聚逻辑，不做优先级覆盖 | — |

### 3.7 逆转信号（Reversal Signal）

**定义**：逆转信号是低概率、极端影响的事件信号，触发时可逆转此前所有负向判断。

**设计来源**：寒武纪 2025 年 AI 大模型爆发——营收从 7 亿→65 亿，利润从 -8 亿→+20 亿，市值突破万亿。这一"范式飞跃"完全逆转了此前 4 年的所有负向信号。

**与普通信号的区别**：

| 维度 | 普通信号 | 逆转信号 |
|------|---------|---------|
| 概率 | 中-高（>50%） | 低（<20%） |
| 影响幅度 | 渐进式 | 突变式（可导致 risk_level 从 critical→low） |
| 可预测性 | 时序可预期 | 范式外冲击 |
| 处理方式 | 参与风险等级计算 | 触发既有评分的重新校准 |

**逆转信号模板**：
```yaml
reversal_signal:              # C9通道专用（可选）
  detected: false             # 是否检测到范式外冲击
  baseline: ""                # 当前负向判断基线
  reversal_trigger: ""        # 什么条件会使基线逆转
  early_indicators: []        # 可观测的早期拐点信号
  historical_precedent: ""    # 类似逆转的历史案例
```

**处理规则**：
1. 逆转信号触发时标注 `reversal_signal_detected: true`
2. 所有受影响的既有风险条目 risk_level 降级 1-2 档
3. 逆转信号本身不评分——只触发既有评分的重新校准
4. 属于"Pre-IPO 本体论外"监控项——参见 contagion-matrix.md C9 通道

### 3.8 管理层执行力代理指标

**设计来源**：九号公司从 52% 小米依赖→4% 的成功转型，本质上是管理层执行能力的胜利。GateKeeper 的风险导向设计使其天然低估执行力，本节提供辅助判断框架。

**代理指标模板**（可选，不计分）：
```yaml
execution_proxy:
  commitment_track_record:     # 历史承诺兑现
    - claim: ""                # 管理层曾公开做出的承诺
      outcome: "met|missed|partial|unknown"
  launch_track_record:         # 新产品按时发布
    on_time: 0
    delayed: 0
    notable_delays: []
  pre_ipo_milestones:          # IPO筹备里程碑
    - milestone: ""
      status: "achieved|delayed|missed"
```

**使用原则**：
- 以上指标**不参与风险评分**——仅作为信号解读的辅助上下文
- 若管理层有兑现承诺的历史 → 现有负向信号权重可酌情降低
- 若管理层有延迟/失约历史 → 现有负向信号权重应酌情升高
- 缺失数据时标注 `unknown`，不做推断

## 4. 信号驱动的工作流

```
风险识别（Scanner Step 2）
    │
    ▼
信号清单生成（新增 Step 2.5）
    │  对每条 Critical/High 风险，按模板输出 signal_watchlist
    │
    ▼
传染检测（Step 3.5，参见 contagion-matrix.md）
    │  检查跨维度传染信号对
    │
    ▼
汇聚与冲突标注（Step 3）
    │
    ▼
质量门禁（Step 4）
    │  G1.5 信号完备 → G1.6 交叉信号一致性 → G1.7 异议角色加权
    │
    ▼
输出报告
    │  风险矩阵 + 信号清单 + 优先级冲突标注 + 传染警报 + 逆转信号监测
```

## 5. 质量门禁补充

**G1.5: 信号完备（Signal Completeness）**：每条 critical/high 风险必须附带 signal_watchlist（≥2 正向 + ≥2 负向 + ≥1 what_must_go_right）。不通过标注 `signal_incomplete`，最多重试一次。

**G1.6: 交叉信号一致性（Cross-Signal Consistency）**：同一风险条目内的跨层级信号冲突（如 T1+ vs T3-）按 §3.6 优先级矩阵处理。T1 信号优先于 T3，被覆盖信号标注 `overridden_by_T1`。参见 references/guardrails/quality-gates.md。不做拒绝——仅标注。

**G1.7: 异议角色加权（Dissenting-Role Escalation）**：当某一角色对同一风险的 risk_level 高于其他角色 ≥2 档时，触发异议加权（×1.5），在风险矩阵中置顶并标注 `dissenting_role`。不做拒绝——信息增强。
