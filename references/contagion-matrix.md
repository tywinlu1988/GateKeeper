# 跨维度风险传染矩阵（Contagion Matrix）

> 单一节点风险不会孤立存在。本矩阵定义四节点间的风险传染通道、放大因子和检测信号。
> 所有 Scanner 节点在完成本节点分析后，必须对照本矩阵检查是否存在跨维度传染激活信号。

> ⚠️ **内嵌案例时效警示**：本文件中的历史案例（孚能科技 2021、敏芯股份 2019-2023、寒武纪 2019-2025、2019 年补贴退坡等）均为**历史参照**（as_of 2019-2025），仅供模式匹配。禁止将这些案例中的数值（如市值跌幅、毛利率）当作当前市场事实引用；在风险条目中使用案例数据时，`data_as_of` 必须填案例发生期。

## 1. 传染通道定义

```
                    ┌──────────────────────────┐
                    │      行业/业务定位        │
                    │   (industry-scanner)      │
                    └──────────┬───────────────┘
                               │ ①市场定位削弱→盈利压力
                               │ ②赛道天花板→估值压缩
                    ┌──────────▼───────────────┐
                    │      技术/知识产权        │
                    │   (tech-scanner)          │
                    └──────────┬───────────────┘
                               │ ③IP丧失→减值+法律成本
                               │ ④技术替代→市占率坍塌
                    ┌──────────▼───────────────┐
                    │      财务合规             │
                    │   (finance-scanner)       │
                    └──────────┬───────────────┘
                               │ ⑤盈利失速→估值杀
                               │ ⑥现金流危机→竞争劣势
                    ┌──────────▼───────────────┐
                    │      定价/发行            │
                    │   (pricing-scanner)       │
                    └──────────────────────────┘

         跨节点传染：
         ⑦ 竞争对手行动 → 供应商/客户连锁反应
         ⑧ 政策/监管变化 → 多维同时冲击
```

## 2. 传染矩阵

| ID | 源头节点 | 目标节点 | 传染通道 | 放大因子 | 检测滞后期 | 历史案例 |
|----|---------|---------|---------|---------|-----------|---------|
| C1 | industry | finance | 市场份额下降→营收增速放缓→毛利率承压→盈利下滑 | 2-3× | 2-4季度 | 孚能科技：市占率从3.3%→1.95%→毛利率从23%→0.5% |
| C2 | industry | pricing | 行业天花板被质疑→可比公司估值下调→发行估值打折 | 1.5-2× | 即时-1季度 | 2019年新能源汽车补贴退坡→全行业估值压缩 |
| C3 | tech | finance | 核心专利败诉→停产+赔偿+减值→利润断崖 | 3-5× | 即时-2季度 | 敏芯股份：歌尔专利诉讼→产品停售+400万赔偿 |
| C4 | tech | industry | 技术路线被替代→产品竞争力丧失→市场份额坍塌 | 3-5× | 4-8季度 | 沃特玛：圆柱路线被淘汰→2018年破产重整 |
| C5 | finance | pricing | 盈利持续低于预期→戴维斯双杀（盈利↓+估值↓）| 2-3× | 1-2季度 | 寒武纪：上市即亏→市值从1200亿→240亿（-80%）|
| C6 | finance | industry | 现金流危机→削减研发/销售→产品迭代放缓→竞争力削弱 | 2-4× | 4-8季度 | 多个二线电池厂因现金流断裂退出市场 |
| C7 | external | all | 竞争对手重大突破→客户/供应商转向→全链冲击 | 2-4× | 1-4季度 | 华为自研AI芯片→寒武纪IP收入-41% |
| C8 | external | all | 政策/监管突变→补贴退坡/准入收紧/关税→多维同时承压 | 3-5× | 即时-2季度 | 2019年补贴退坡50%→全产业链利润压缩 |
| C9 | external | all | 外部范式飞跃（AI/能源/材料突破）→全节点逆转 | N/A | 跨周期（>8Q） | 寒武纪2025：AI大模型→芯片需求爆发→4年亏损逆转 |

> **C9 特殊说明**：C9 "外部范式飞跃"通道属于 Pre-IPO 本体论外的监控项。触发概率极低（<5%），但影响是系统性的。C9 触发时不应直接修改风险条目，而应触发"逆转信号"处理（参见 signal-watchlist.md §3.7）。

## 3. 传染激活检测信号

每个 Scanner 完成本节点分析后，必须检查以下信号对。当**同一对中 ≥2 条信号同时触发**时，标记为"传染激活"，在 node_artifact 中增加 `contagion_alert` 字段。

### C1: 行业→财务

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 公司市占率稳定或上升 | 市占率变化 ≥ 0% |
| + 正向（无传染） | 行业增速 > 公司营收增速 | — |
| - 负向（传染激活） | 公司市占率连续 2 期下滑 | 累计下滑 ≥ 1pp |
| - 负向（传染激活） | 前 3 大客户中 ≥1 家减少采购 | 采购额下降 ≥ 20% |
| - 负向（传染激活） | 公司毛利率 < 行业均值 | 差距 > 5pp |

### C2: 行业→定价

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 可比公司估值稳定或上升 | TTM PE 3 个月变动 ≥ 0% |
| + 正向（无传染） | 行业增速预期上修 | — |
| - 负向（传染激活） | 可比公司估值连续下调 | TTM PE 3 个月降幅 ≥ 20% |
| - 负向（传染激活） | 行业天花板被公开质疑（主流研报/媒体下调 TAM） | ≥ 1 篇 |
| - 负向（传染激活） | 同赛道新股发行估值中枢下移 | 近 2 只可比新股 PE 较前批次低 ≥ 20% |

### C3: 技术→财务

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 核心专利无未决诉讼 | 0 件未决 |
| + 正向（无传染） | 研发费用率稳定在行业可比范围内 | — |
| - 负向（传染激活） | 核心专利涉诉（侵权或权属纠纷） | ≥ 1 件 |
| - 负向（传染激活） | 涉诉产品线收入占比 > 10% | — |
| - 负向（传染激活） | 一审败诉或不利裁决 | — |

### C4: 技术→行业

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 公司技术路线市占率稳定或上升 | — |
| + 正向（无传染） | 替代路线无量产/商业化进展 | — |
| - 负向（传染激活） | 头部企业 ≥ 2 家转向替代路线 | — |
| - 负向（传染激活） | 替代路线核心性能指标超越公司路线 | ≥ 30% |
| - 负向（传染激活） | 行业标准修订排除公司路线 | — |

### C5: 财务→定价

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 盈利达到或超过招股书预测 | — |
| + 正向（无传染） | 经营性现金流为正 | — |
| - 负向（传染激活） | 上市后首份财报盈利低于招股书预测 | 差距 > 20% |
| - 负向（传染激活） | 扣非净利润转负 | — |
| - 负向（传染激活） | 应收账款/营收比值连续 2 期攀升 | 累计增幅 > 5pp |

### C6: 财务→行业

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 经营现金流为正且覆盖研发投入 | — |
| + 正向（无传染） | 现金储备充足 | ≥ 12 个月运营成本 |
| - 负向（传染激活） | 经营现金流连续 2 期为负 | — |
| - 负向（传染激活） | 研发费用率连续 2 期下降且低于同业 | 降幅 ≥ 2pp |
| - 负向（传染激活） | 债务展期 / 供应商账期异常拉长 | ≥ 1 项 |

### C7: 外部竞争冲击→全部节点

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 公司与主要客户有长期合同锁定 | 合同期 ≥ 3年 |
| + 正向（无传染） | 技术路线与头部企业差异化 | — |
| - 负向（传染激活） | 第一大客户宣布自研替代方案 | — |
| - 负向（传染激活） | 头部企业推出同品类但价格低 ≥ 20% 的产品 | — |
| - 负向（传染激活） | 公司核心技术人员离职加入竞对 | — |

### C8: 政策/监管突变→全部节点

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（无传染） | 行业政策保持稳定或加码 | — |
| + 正向（无传染） | 发行人不在监管收紧/重点检查范围 | — |
| - 负向（传染激活） | 补贴/优惠政策退坡或退出时间表明确 | ≥ 1 项 |
| - 负向（传染激活） | 行业准入或监管规则收紧（新法规、新检查机制） | — |
| - 负向（传染激活） | 贸易/关税环境恶化影响核心供应链 | — |

### C9: 外部范式飞跃→全部节点

| 信号方向 | 检测信号 | 阈值 |
|---------|---------|------|
| + 正向（范式有利） | 行业获得政策/资本/技术重大突破 | 影响核心业务 |
| + 正向（范式有利） | 公司技术路线外部需求爆发 | 市场增速 > 100% YoY |
| - 负向（范式不利） | 替代路线获不可逆产业/政策支持 | 头部企业 > 50% 转向 |
| - 负向（范式不利） | 公司核心技术路线被新行业标准排除 | — |

注意：C9 触发时 → 优先触发 signal-watchlist.md §3.7 逆转信号处理，而非常规强度分级。

## 4. 传染强度分级

| 级别 | 条件 | 处理 |
|------|------|------|
| 🟢 无传染 | 所有信号对均为正向 | 正常输出，无额外标注 |
| 🟡 弱传染 | 1条信号对触发负向 | 标注 `contagion_alert: watch`，提示关注 |
| 🟠 中传染 | 2-3条信号对触发负向 | 标注 `contagion_alert: active`，在风险矩阵中增加"传染路径"列 |
| 🔴 强传染 | ≥4条信号对触发负向 | 标注 `contagion_alert: critical`，触发跨节点联合分析建议 |

**alert 状态转移**（解决 watch 无限延续问题）：
- **升级**：负向信号对数量增加 → 按上表升档
- **维持**：下次推演信号对数量不变 → 保持原级别，记录复测时间
- **解除**：下次推演该通道信号对全部回到正向 → 降为 🟢，标注 `contagion_resolved: {channel, resolved_at}`，保留历史记录不删除

## 5. 使用方式

每个 Scanner 在 Step 3（汇聚与冲突标注）之后，插入以下步骤：

```
Step 3.5: 传染检测

1. 读取 references/contagion-matrix.md
2. 对照本节点的风险条目，逐条检查对应的传染信号对
3. 若触发 ≥1 条负向信号 → 在 node_artifact 中添加 contagion_alert 字段
4. 若触发 ≥4 条（强传染）→ 建议用户触发跨节点联合分析
5. 叠加检查 → 若 ≥2 条通道同时负向激活 → 按 §6 叠加规则计算放大因子
```

## 6. 传染叠加规则（Superposition）

> 多通道同时激活时，综合效果大于单一通道之和。
> 设计来源：寒武纪 C7+C5+C4 同时激活 → -84.5% 跌幅超任何单通道预测区间。

### 6.1 叠加定级（v0.5.0 起定性化）

> 数值放大因子（1.5×/2.0×）无实证校准，伪精确输出损害报告可信度——已弃用。
> 叠加输出为通道列表 + 定级，不再输出数值因子。

| 同时负向激活通道数 | 叠加定级 | 输出形式 |
|-----------------|---------|---------|
| 1 条 | watch | `superposition.active_channels: [Cx]`，`alert_level: watch` |
| 2-3 条 | active | `active_channels: [Cx, Cy]`，`alert_level: active`；报告列出各通道激活证据 |
| ≥4 条 | critical | `alert_level: critical`，触发跨节点联合分析建议 |

### 6.2 适用规则

1. 仅计算负向激活通道（正向不计入叠加计数）
2. C9 不计入叠加计数（范式飞跃是独立事件）
3. 叠加定级不机械修改单条 risk_level——升级逻辑由各节点 Step 3 汇聚时人工（执行体）判断并在 rationale 中说明
4. 在 node_artifact 中记录叠加字段（schema S2 superposition）
