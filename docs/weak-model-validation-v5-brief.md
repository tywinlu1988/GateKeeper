# 第五轮弱模型验证指令（v0.6.0）

> 用途：把本文件整体交给弱模型执行环境（如 DeepSeek），作为第五轮全流程验证的任务书。
> 前四轮验证对象：v0.4.0/0.4.1/0.4.2/0.4.3（频准激光）；本轮验证对象：**v0.6.0 三产物体系 + 监控引擎**。

## 1. 项目选择

**强制要求：选择一个新项目，禁止使用频准激光或宇树科技**（前两案已入库为回归基准，重跑会过拟合——知识库中已有其事实卡与失败模式清单）。
建议：一个已完成科创板发行或处于发行阶段的新公司（发行结果公告、招股书、问询函公开可查）。

## 2. 执行要求

1. 下载 GateKeeper **v0.6.0 release**（GitHub: tywinlu1988/GateKeeper）到独立沙盒目录
2. 规则文件只读（N12）——推演前后 `git status` 必须干净
3. full-chain deep 全链路：ipo-router → industry → tech → finance → pricing
4. 最终交付：final-report.html（主交付物）+ 三个分拆件在根目录；全部过程文件进 artifacts/ 子目录
5. 落盘完整过程日志（查询记录、门禁逐项结果、G7 清单）

## 3. 验收清单（场景 7 v0.5.x 版 + 场景 8）

### 场景 7：v0.5.x 三产物机制（10 项）

| # | 检查点 |
|---|--------|
| 1 | search_log 三角色真实分化（≥2 条角色独有查询） |
| 2 | G7 清单含「距今月数」计算列且判定正确 |
| 3 | D4 标注数值不出现于结论位（回灌按数值扫描） |
| 4 | 最终报告与三产物均含 GateKeeper-Template 标记 |
| 5 | 制品-日志对账一致（条目数/查询数可对账） |
| 6 | market_snapshot 八项全带具体数值+来源 URL |
| 7 | 可比估值双来源/交叉计算，聚合数字可复算 |
| 8 | ID 完整枚举（pre-ipo-investor/buy-side/media） |
| 9 | key_data_points 附 source_ref 或 [UNLOGGED] |
| 10 | deep 每角色 ≥1 次一手披露查询 |

### v0.5.0 三产物专项（6 项）

| # | 检查点 |
|---|--------|
| 11 | 内核清单 ≤15 条且含 应对动作/责任归属/时限/反面论证 |
| 12 | priced_in 每类（priced-in/partially/unpriced）≥1 条且附推导依据，unknown=0 |
| 13 | suggested_response 全部为可执行动作（无"关注XX"空泛表述） |

| 16 | 交付目录组织：根目录仅 4 个可读文件，过程文件在 artifacts/ |

### 场景 8：monitoring-run 监控引擎（5 项）

| # | 检查点 |
|---|--------|
| 17 | Router 将"引用 plan_id + 监控/季报后"类输入路由到 monitoring-run |
| 18 | 无 previous_run_id 时 monitor-runner 拒绝执行 |
| 19 | 每条信号判定为"阈值 vs 最新值"显式比较（G9） |

## 4. 产物约定

- 全部产物落盘到用户指定目录，与 Gatekeeper 规则库分离
- 过程日志必须包含：全部查询词列表、每节点门禁逐项结果、G7 清单、制品-日志对账表
- 最终回复附：检查点 1-21 的 ✅/❌ 汇总表 + 执行中发现的问题清单
